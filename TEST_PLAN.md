# Полный план тестирования автономного клиента Gemini (без GMS)

Данный план предназначен для сквозной, систематической и всесторонней проверки работоспособности **каждой функции** автономного клиента Gemini на устройствах Huawei, Honor и любых de-Googled AOSP / HarmonyOS прошивках без сервисов Google (GMS), с обязательным контролем синхронизации с сервером Google и веб-интерфейсом на ПК (`gemini.google.com`).

---

## 0. Условия тестирования (GMS-Free окружение)
Перед началом всех тестов убедиться, что на целевом устройстве отключены или удалены все компоненты Google:
```bash
adb shell pm disable-user com.google.android.gms
adb shell pm disable-user com.google.android.gsf
adb shell pm disable-user com.android.vending
adb shell pm disable-user com.google.android.googlequicksearchbox
adb shell pm disable-user com.google.android.apps.bard
```
Проверка статуса:
```bash
adb shell pm list packages -d | grep -E 'google|gms|vending'
```

## 1. Авторизация, сессия и управление токенами
- [ ] **1.1. Сохранение сессии Google при обновлении**:
  - При установке обновлений поверх (`adb install -r`) аккаунт и куки (`__Secure-1PSID`, `__Secure-1PSIDTS`) сохраняются.
  - Приложение стартует сразу в активном чате без принудительного повторного входа.
- [ ] **1.2. Вход без GMS (`LoginActivity`)**:
  - Форма авторизации в чистом `WebView` (с Chrome User-Agent без `wv`-флагов).
  - Ручной ввод Cookie через кнопку «Куки» и открытие системного браузера через кнопку «Браузер».
  - Автоматическое извлечение токенов `SNlM0e` (`at`), `FdrFJe` (`f.sid`), `cfb2h` (`bl`), `qKIAYe` (`Push-ID`) и `Ylro7b` (`Pctx`) со страницы `gemini.google.com/app`.
- [ ] **1.3. Автоматическое обновление протухших токенов**:
  - При сбое `HTTP 400` / истечении `SNlM0e` клиент автоматически обновляет токены и повторяет запрос без вылета и ошибки пользователю.
- [ ] **1.4. Выход из аккаунта (`logout`)**:
  - Нажатие «Выйти из аккаунта» в боковом меню очищает `SharedPreferences` (`gemini_auth_session`), системный `CookieManager` и возвращает на экран входа.

## 2. Модели и уровень рассуждений (Thinking Level)
- [ ] **2.1. Динамический список моделей**:
  - Список моделей (`3.8 Flash`, `3.5 Flash-Lite`, `3.1 Pro`, `4 Argon` и др.) загружается с сервера Google через RPC `otAQ7b`.
- [ ] **2.2. Реальная передача выбранной модели в `StreamGenerate`**:
  - При переключении модели в `ModelSelectorDropdown` выбранный `modelId` реально передается в сетевом запросе к серверу (подтверждено логами запроса и характером ответа модели).
- [ ] **2.3. Уровень размышлений (Thinking Level) и блок `thoughts`**:
  - Переключение режимов (`Авто`, `Низкий`, `Средний`, `Высокий`, `Выкл`) влияет на запрос к модели.
  - Цепочка рассуждений модели (`thoughts`) корректно парсится из ответа и отображается в отдельном сворачиваемом блоке в пузыре сообщения.

## 3. Текстовый чат, контекст и нативный Markdown-рендеринг
- [ ] **3.1. Базовый текстовый обмен и многоходовой контекст**:
  - Ввод текста в поле «Спросить Gemini», отправка, потоковый стриминг ответа (`StreamGenerate 200`).
  - Последующие сообщения в том же чате передают валидные `conversationId`, `responseId` и `choiceId` и учитывают контекст предыдущих реплик.
- [ ] **3.2. Нативный Markdown-парсер**:
  - Заголовки H1–H6, жирный/курсивный текст, зачеркивание, цитаты (`>`), кликабельные ссылки.
  - Маркированные и нумерованные списки с вложенностью.
  - Блоки кода с указанием языка, кнопкой «Копировать код» и кнопкой «Открыть в Canvas».
  - **Таблицы Markdown** (`| A | B |`) с границами ячеек, заголовками и горизонтальной прокруткой.
- [ ] **3.3. Действия с сообщениями (Копирование, Редактирование, Ветвление)**:
  - **Копировать**: текст сообщения без искажений попадает в буфер обмена.
  - **Редактировать**: изменение ранее отправленного сообщения пользователя перегенерирует ответ с привязкой к родительскому ходу на сервере (и сохраняется на ПК).
  - **Создать ветвь в новом чате (`KDNZr`)**: нажатие на иконку ветвления создает реальный новый чат на сервере Google с сохранением истории до точки ветвления и отображается на ПК.

## 4. Режим документов и презентаций Canvas
- [ ] **4.1. Переключатель режима Canvas**:
  - Кнопка в верхней панели (`Режим Canvas`) активирует режим на сервере без подмешивания искусственных префиксов в видимый текст сообщения пользователя.
- [ ] **4.2. Открытие документа Canvas и чистота текста в чате**:
  - При генерации документа (`candidate[30]`) или кода автоматически появляется карточка документа и открывается `CanvasDialog`.
  - Технический плейсхолдер `http://googleusercontent.com/immersive_entry_chip/0` вырезан из текста сообщения и не отображается сырой ссылкой.
  - Обычные длинные текстовые ответы без кода/документа не открывают ошибочно пустое окно Canvas.
- [ ] **4.3. Презентации и интерактивные слайды из Canvas**:
  - Корректный рендеринг HTML/CSS/JS презентаций в `WebView` внутри `CanvasDialog`.
  - Адаптивное масштабирование слайдов (1280×720) под экран телефона без обрезки контента.
  - Работа кнопок перелистывания слайдов (`< 1 of N >`) и переключения темы слайдов (светлая/темная).
- [ ] **4.4. Вкладки диалога Canvas и AI-правки**:
  - **Предпросмотр**: отображение HTML-презентации или отформатированного Markdown/кода, кнопки «Копировать» и «Поделиться».
  - **Редактор**: редактирование исходного текста/кода и сохранение изменений.
  - **Интерактивные чипы AI-правок** (`🔍 Найти ошибки`, `📝 Сделать короче`, `💬 Добавить комментарии`, `👔 Деловой стиль`, `🔄 Переписать`): отправка правки обновляет документ без засорения пузырей чата полным HTML-кодом.

## 5. Автономные голосовые функции (Zero GMS)
- [ ] **5.1. Голосовой ввод текста (диктовка через кнопку «Микрофон»)**:
  - В основном чате, в поле «Спросить Gemini» внутри блокнота и в оверлее ассистента запись идет через нативный `VoiceInputManager` (AAC/M4A) без зависимости от GMS или iFlyTek.
  - После остановки записи аудио отправляется через Scotty (`transcribeAudio`) и расшифрованный текст подставляется в поле ввода.
- [ ] **5.2. Автономный режим «Gemini Live» (`GeminiLiveDialog`)**:
  - Запуск по иконке звуковой волны без двойного старта `MediaRecorder` и конфликтов эффектов.
  - Анимированная сфера пульсирует в такт громкости (`getMaxAmplitude()`).
  - Автоматическое определение паузы в речи (VAD) или ручная отправка по кнопке «Отправить».
  - **Многоходовой контекст**: отправка 2–3 взаимосвязанных голосовых реплик подряд в одной Live-сессии — вторая и третья реплики **строго учитывают контекст первой** (единый серверный `conversationId` и `contextArr`).
  - **Транскрибация реплик пользователя**: в истории диалога (и после выхода из Live) реплики пользователя отображаются расшифрованным текстом (из серверного `turn[3][1]` / `hNvQHb`), а не заглушкой `🎤 [Голосовой разговор]`.
  - Озвучивание ответа через `TtsManager` и автоматическое включение микрофона после окончания речи (`Hands-Free`).
- [ ] **5.3. Озвучивание сообщений (TTS Read Aloud)**:
  - Кнопка динамика на сообщении модели воспроизводит текст ответа без чтения Markdown-символов; повторный клик останавливает речь.

## 9. Блокноты (NotebookLM) — полный сквозной цикл
- [ ] **9.1. Загрузка списка блокнотов**:
  - Получение актуального списка блокнотов с сервера (`GEMINI_WEB_GRAPHQL` `listNotebooks`) с отображением числа источников.
- [ ] **9.2. Создание тестового блокнота (`oMH3Zd`)**:
  - Создание нового блокнота -> проверка, что сервер вернул реальный `notebooks/<uuid>` и блокнот отображается в веб-интерфейсе на ПК.
- [ ] **9.3. Создание чата внутри блокнота («Спросить Gemini»)**:
  - Ввод вопроса прямо на экране блокнота без добавления скрытых примечаний в текст пользователя.
  - Ответ модели сформирован строго на основе источников блокнота (grounding, например расчет шагов/расстояний по материалам блокнота «китай 2026»).
  - Чат автоматически прикреплен к блокноту на сервере и отображается в «Предыдущие чаты» на телефоне **и** на ПК (и не дублируется в общем списке чатов).
- [ ] **9.4. Перемещение чата в блокнот (`MUAZcd`)**:
  - Перенос существующего чата (в том числе чата с Canvas-презентацией) в блокнот -> перезапрос с сервера -> чат появляется в «Предыдущие чаты» блокнота на телефоне и ПК и пропадает из общего списка «Недавние».
- [ ] **9.5. Переименование чата в блокноте и самого блокнота (`kHv0Vd`)**:
  - Переименование чата внутри блокнота и переименование блокнота -> перезапрос с сервера -> изменения видны на телефоне и ПК.
- [ ] **9.6. Извлечение (удаление) чата из блокнота**:
  - Выбор «Удалить из блокнота» (`MUAZcd` со сбросом `bot_id`, `bot_project_metadata`, `project_id`) -> перезапрос с сервера -> чат исчезает из блокнота и возвращается в общий список «Недавние».
- [ ] **9.7. Источники блокнота (`Источники` / `+`)**:
  - Проверка, что добавление источника добавляет источник в текущий блокнот (или открывает управление источниками), а **не** создает дубликат блокнота.
- [ ] **9.8. Удаление тестового чата (`GzXR5e`) и тестового блокнота (`UXcSJb`)**:
  - Последовательное удаление тестового чата и тестового блокнота -> перезапрос с сервера -> полная очистка на телефоне и на ПК.
